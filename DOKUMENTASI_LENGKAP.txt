🔧 NATIVE ANDROID APIs (Kotlin):
────────────────────────────────────────────────────────────────────────────

1. MediaProjection API
   ├─ Package: android.media.projection.MediaProjection
   ├─ Fungsi: Capture FULL SCREEN (termasuk app lain, system UI, dll)
   ├─ Komponen:
   │  • MediaProjectionManager: Service untuk request permission
   │  • MediaProjection: Object untuk akses screen
   │  • VirtualDisplay: Display virtual untuk mirror screen
   │  • ImageReader: Reader untuk baca pixel data
   └─ Konsep: Screen mirroring & frame capturing

2. UsageStatsManager API
   ├─ Package: android.app.usage.UsageStatsManager
   ├─ Fungsi: Track aplikasi yang digunakan user
   ├─ Method:
   │  • queryUsageStats(): List app yang dipakai dalam rentang waktu
   │  • Ambil app paling recent berdasarkan lastTimeUsed
   └─ Konsep: App usage tracking & analytics

3. ImageReader & Image
   ├─ Package: android.media.ImageReader, android.media.Image
   ├─ Fungsi: Baca pixel data dari surface
   ├─ Format: RGBA_8888 (32-bit color)
   ├─ Buffer: 3 images (untuk menghindari "no image available")
   └─ Konsep: Low-level graphics buffer

4. VirtualDisplay
   ├─ Package: android.hardware.display.VirtualDisplay
   ├─ Fungsi: Display virtual yang mirror screen fisik
   ├─ Flag: VIRTUAL_DISPLAY_FLAG_AUTO_MIRROR
   └─ Konsep: Display management

5. Foreground Service
   ├─ Package: android.app.Service
   ├─ Fungsi: Service yang tetap running bahkan app di background
   ├─ Required: Android 14+ wajib untuk MediaProjection
   ├─ Type: FOREGROUND_SERVICE_TYPE_MEDIA_PROJECTION
   └─ Konsep: Background processing & notifications

6. MethodChannel
   ├─ Package: io.flutter.plugin.common.MethodChannel
   ├─ Fungsi: Bridge komunikasi Flutter ↔️ Native Android
   ├─ Channel names:
   │  • "com.reflvy.app/screen_capture"
   │  • "com.reflvy.app/app_detection"
   └─ Konsep: Platform channel communication

7. Bitmap & ByteArray
   ├─ Package: android.graphics.Bitmap
   ├─ Fungsi: Convert pixel data → PNG image
   ├─ Flow: Image → Bitmap → PNG ByteArray → Flutter
   └─ Konsep: Image encoding & compression

                        4. KONSEP & PATTERN YANG DIGUNAKAN
================================================================================

🎨 DESIGN PATTERNS:
────────────────────────────────────────────────────────────────────────────

1. BRIDGE PATTERN (Platform Channel)
   ├─ Masalah: Flutter tidak bisa akses Android API langsung
   ├─ Solusi: MethodChannel sebagai bridge
   ├─ Implementasi:
   │  • Flutter (Dart) ←→ MethodChannel ←→ Native (Kotlin)
   │  • Async communication dengan Future/Result
   └─ Benefit: Separation of concerns, platform independence

2. SERVICE LAYER PATTERN
   ├─ Layer:
   │  • UI Layer (Screens/Widgets)
   │  • Service Layer (Business logic)
   │  • Data Layer (Native APIs)
   ├─ Implementasi:
   │  • AutoScreenshotService: Orchestrator
   │  • ScreenCaptureService: Bridge
   │  • AppDetectionService: Bridge
   └─ Benefit: Loose coupling, testability

3. OBSERVER PATTERN (GetX Reactive)
   ├─ Konsep: UI observe state changes
   ├─ Implementasi:
   │  • RxBool isRecording
   │  • RxInt screenshotCount
   │  • RxString currentApp
   │  • RxList screenshots
   ├─ UI: Obx(() => Text('${controller.screenshotCount}'))
   └─ Benefit: Automatic UI updates, no setState()

4. HELPER PATTERN
   ├─ Class: ScreenCaptureHelper, AppDetectionHelper
   ├─ Fungsi: Encapsulate native API logic
   └─ Benefit: Code reusability, single responsibility

5. TIMER PATTERN
   ├─ Konsep: Periodic execution
   ├─ Implementasi: Timer.periodic(Duration(seconds: 5), callback)
   └─ Benefit: Automatic scheduling, easy cancellation


🧠 KONSEP FUNDAMENTAL:
────────────────────────────────────────────────────────────────────────────

1. ASYNC PROGRAMMING
   ├─ Dart: async/await, Future
   ├─ Kotlin: Callback, Handler
   ├─ Contoh:
   │  • Future<bool> startCapture() async { ... }
   │  • val result = await platform.invokeMethod('startCapture')
   └─ Benefit: Non-blocking operations

2. PLATFORM CHANNEL COMMUNICATION
   ├─ MethodChannel: Method calls (with return value)
   ├─ Message format: Binary serialization
   ├─ Data types: String, int, bool, List, Map, Uint8List
   └─ Konsep: Cross-platform interop

3. MEMORY MANAGEMENT
   ├─ Android: Manual cleanup (recycle Bitmap, close Image)
   ├─ Flutter: Garbage collection
   ├─ Penting:
   │  • image.close() → free buffer
   │  • bitmap.recycle() → free native memory
   └─ Masalah jika tidak: Memory leak

4. PERMISSIONS MODEL (Android 6.0+)
   ├─ Normal permissions: Auto granted
   ├─ Dangerous permissions: Request at runtime
   ├─ Special permissions: User harus buka Settings
   │  • PACKAGE_USAGE_STATS
   └─ Konsep: Privacy & security

5. FOREGROUND SERVICE
   ├─ Tujuan: Keep service alive
   ├─ Requirement: Notification visible
   ├─ Android 14+: Wajib untuk MediaProjection
   └─ Konsep: User awareness & control

6. IMAGE PROCESSING PIPELINE
   ├─ Flow:
   │  Screen → VirtualDisplay → Surface → ImageReader → Image (YUV/RGB)
   │  → ByteBuffer → Bitmap (ARGB_8888) → PNG (compressed) → ByteArray
   ├─ Format:
   │  • RGBA_8888: 4 bytes per pixel (R, G, B, Alpha)
   │  • PNG: Lossless compression
   └─ Konsep: Graphics pipeline

================================================================================
                          7. KEY TECHNICAL DETAILS
================================================================================

🔑 MediaProjection:
────────────────────────────────────────────────────────────────────────────
• Introduced: Android 5.0 (API 21)
• Permission: System dialog "Start capturing screen?"
• Scope: Capture SEMUA yang ada di layar (full screen)
• Duration: Sampai user stop atau app closed
• Requirement: Foreground Service (Android 14+)

🔑 VirtualDisplay:
────────────────────────────────────────────────────────────────────────────
• Fungsi: Display virtual yang "mirror" screen fisik
• Output: Surface (bisa ImageReader, SurfaceView, dll)
• Flag AUTO_MIRROR: Otomatis sync dengan screen fisik
• Performance: Real-time rendering (60fps di flagship device)

🔑 ImageReader:
────────────────────────────────────────────────────────────────────────────
• Buffer: Queue of images (kita pakai 3)
• Format: RGBA_8888 (4 bytes per pixel)
• Method:
  - acquireLatestImage(): Ambil image terbaru (skip yang lama)
  - acquireNextImage(): Ambil image next dalam queue
• PENTING: Harus close() setiap Image untuk free buffer!

🔑 UsageStatsManager:
────────────────────────────────────────────────────────────────────────────
• Introduced: Android 5.0 (API 21)
• Fungsi: Track app usage statistics
• Permission: PACKAGE_USAGE_STATS (special permission)
• Query: queryUsageStats(interval, beginTime, endTime)
• Data: Package name, total time, last time used
• Limitasi: Update interval ~1 detik (tidak real-time)

🔑 Aggressive Capture Mode:
────────────────────────────────────────────────────────────────────────────
• Strategi: Langsung capture tanpa wait
• Pro: No artificial delay, fast response
• Con: First capture might fail (VirtualDisplay belum ready)
• Solution: Auto retry setiap 5 detik
• Expected: Capture ke-2 biasanya sukses (VirtualDisplay sudah render)

🔑 Timer Strategy:
────────────────────────────────────────────────────────────────────────────
• Timer.periodic(Duration(seconds: 5), callback)
• Start timer SEBELUM capture pertama
• Capture pertama langsung (tidak tunggu 5 detik)
• Jika gagal: Retry otomatis di cycle berikutnya
• Cancel: timer.cancel() saat stop monitoring

================================================================================
                       8. TROUBLESHOOTING & COMMON ISSUES
================================================================================

❌ ISSUE 1: "Permission Denied" saat request MediaProjection
────────────────────────────────────────────────────────────────────────────
Penyebab:
  • User klik "Cancel" di dialog
  • Foreground Service belum ready (Android 14+)
  
Solusi:
  • Check permission result di onActivityResult
  • Start Foreground Service SEBELUM request permission
  • Delay 500ms setelah start service

❌ ISSUE 2: "No image available" saat capture
────────────────────────────────────────────────────────────────────────────
Penyebab:
  • VirtualDisplay belum render frame pertama
  • ImageReader buffer penuh (tidak di-close)
  
Solusi:
  • Aggressive mode: Return null, retry otomatis
  • PENTING: image.close() di finally block
  • Increase buffer size (2 → 3)

❌ ISSUE 3: "Usage Stats permission not granted"
────────────────────────────────────────────────────────────────────────────
Penyebab:
  • User belum enable di Settings → Special app access → Usage access
  
Solusi:
  • Detect dengan AppOpsManager.checkOpNoThrow()
  • Show dialog dengan tombol "Open Settings"
  • startActivity(Settings.ACTION_USAGE_ACCESS_SETTINGS)

❌ ISSUE 4: App crash dengan SecurityException
────────────────────────────────────────────────────────────────────────────
Penyebab (Android 14+):
  • MediaProjection tanpa Foreground Service
  
Solusi:
  • Declare service di AndroidManifest.xml
  • Set foregroundServiceType="mediaProjection"
  • Call startForegroundService() sebelum request permission

❌ ISSUE 5: Memory leak / OutOfMemoryError
────────────────────────────────────────────────────────────────────────────
Penyebab:
  • Bitmap tidak di-recycle()
  • Image tidak di-close()
  • Screenshot tidak di-cleanup setelah upload
  
Solusi:
  • ALWAYS recycle Bitmap: bitmap.recycle()
  • ALWAYS close Image: image.close() di finally
  • Delete screenshot setelah upload sukses

❌ ISSUE 6: Screenshot hitam / blank
────────────────────────────────────────────────────────────────────────────
Penyebab:
  • App dengan FLAG_SECURE (banking apps)
  • Screen off / locked
  
Solusi:
  • Tidak bisa capture app dengan FLAG_SECURE (security restriction)
  • Skip capture saat screen off

1. Clear onboarding untuk explain permissions
